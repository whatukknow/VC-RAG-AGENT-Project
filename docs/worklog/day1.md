## Notion 입력용 요약

**막힌 점, 고민**
- Notion 매뉴얼 첫 링크는 본문이 비어 읽히지 않았음
- 이전 요약(파일럿)의 가정이 실제 데이터와 달랐음: RunAnywhere 소개문에는 비용 조건·비교 대상이 없고, 평가셋도 25문항이라 적혀 있었으나 매뉴얼은 30문항(개발 10 / 최종 20)
- 범위를 "비용 절감 하위유형"으로 좁히면 근거 있는 후보가 10~20개뿐이라 서로 다른 30문항을 만들 수 없고, 넓히면 주제가 흐려질 위험이 있었음
- 문서가 짧고(중앙값 401자) 데이터 라이선스가 명시되지 않은 비공식 데이터라 이용 범위가 불확실했음
- 규칙 추출 후보에 kernel, GPU 단어만 겹치는 무관한 회사(사진 공유, 바이오차 등)가 섞였음

**해결방안**
- 내장 브라우저로 접힌 토글을 모두 펼쳐 매뉴얼 전문을 확보
- 잘못된 가정은 정답에 쓰지 않고 "근거 없음" 문항(T20)으로 전환, 평가셋은 매뉴얼대로 30문항(10/20)으로 재설계
- 범위는 AI 추론 인프라 전체로 확정하고 후보 112개를 수동 검토해 core 54 + distractor 14 = 68개 문서로 확정(단어만 겹치는 회사는 혼동 문서로 보존)
- 원문은 저장소에 올리지 않고 문서 ID·원본 URL·재수집 스크립트만 공개, 최종 평가셋은 SHA-256으로 고정

## 3. 핵심 의사결정
| 결정 | 내용 | 이유 |
|---|---|---|
| 주제 | YC 추론 인프라 회사 탐색 | 사용자(투자 심사역)와 오답 위험이 분명하고 혼동 문서(비용 vs 지연시간)를 설계할 수 있음 |
| 문서 범위 | 좁은 하위유형이 아니라 AI 추론 인프라 전체 | 하위유형만으로는 서로 다른 30문항을 만들 수 없음. 근거 있는 후보가 10~20개 수준 |
| 질문 언어 | 영어 | 문서가 영어. 한국어 질문이면 BM25가 어휘를 못 맞춰 하이브리드 비교가 무의미 |
| 목록형 질문 제외 | "조건에 맞는 회사를 모두 나열" 유형은 평가셋에서 제외 | Hit@5는 목록 누락을 측정하지 못함 |
| 성공 기준 | 결과를 보기 전에 확정 (Hit@5 ≥ 14/17, 정답 충족 ≥ 12/17, 근거 적합 ≥ 13/17, 근거 없음 거절 ≥ 2/3) | 결과에 맞춰 기준을 바꾸지 않기 위함 |

## 5. 측정값과 확인한 사실
- 데이터: 6,409개사. 추론·GPU 관련 키워드 후보 214개(느슨한 규칙), 그중 비용 문구가 있는 곳 24개
- 확정 문서 68개의 소개문 합계 약 37.5k자, 중앙값 401자. 기업당 청크가 1~2개 수준
- 평가셋: 근거 인용 36건 모두 원문과 정확히 일치. 근거 없음 5문항은 해당 문서에 정답 정보가 없음을 정규식으로 확인
- 매뉴얼 요건: 평가셋은 30문항(개발 10 / 최종 20), Hit@5 분모는 답변 가능 17문항

## 6. 문제와 해결 (시행착오)
| 문제 | 원인 | 해결 |
|---|---|---|
| Notion 링크가 읽히지 않음 | 본문이 JavaScript 렌더링이고 토글이 접혀 있음 | 내장 브라우저에서 토글을 모두 펼친 뒤 전문 확보 |
| 파일럿(이전 요약)의 예상 정답이 데이터와 다름 | RunAnywhere 소개문에는 "faster and cheaper"만 있고 배포 방식·사용량·비교 대상 조건이 없음 | 해당 가정을 정답에 쓰지 않고 "근거 없음" 문항(T20)으로 전환 |
| 파일럿이 평가셋을 25문항으로 적음 | 매뉴얼은 30문항(10/20) | 30문항으로 재설계 |
| 규칙 추출 후보에 무관한 회사 혼입 | kernel, GPU 같은 단어가 사진 공유·바이오차·설탕 회사에도 매칭 | 수동 검토로 core/distractor를 확정하고, 단어만 겹치는 회사는 혼동 문서로 의도적으로 보존 |
| 데이터 이용 조건 불명 | yc-oss 저장소에 라이선스가 명시되어 있지 않은 비공식 데이터 | 원문은 저장소에 올리지 않고 문서 ID, 원본 URL, 재수집 스크립트만 공개 |
